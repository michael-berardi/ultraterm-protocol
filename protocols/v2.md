# UltraTerm Terminal Protocol v2

This document is the normative UTP v2 wire and reference-client specification. The key words MUST, MUST NOT, SHOULD, SHOULD NOT, and MAY are interpreted as described in RFC 2119.

## 1. Transport

A UTP v2 server MUST listen on `~/.ultraterm/utp.sock`.

- `~/.ultraterm` MUST have mode `0700`; the socket MUST have mode `0600`.
- The server MUST accept same-user local connections only.
- The server MUST NOT expose UTP through TCP or another network listener.

A connection carries UTF-8 JSON Lines: one object request per line and exactly one object response per request, in order. A request MUST NOT exceed 65,536 bytes. Invalid, oversized, or unknown requests return `{"ok":false,"error":"DETAILS"}`. Unknown object fields MAY be ignored. Names are case-sensitive.

## 2. Session identity

Commands return sessions in this shape:

```json
{"id":"SESSION_UUID","slot":1,"title":"Terminal 1","pid":12345,"launchedOmp":true,"launchProfile":"PROFILE_NAME"}
```

`id` identifies one attached process and changes after a restart or profile replacement. `slot` is the user-facing terminal assignment. Destructive plans bind to `id`, never to `slot` alone.

## 3. Commands

### 3.1 `list`

```json
{"cmd":"list"}
{"ok":true,"sessions":[{"id":"SESSION_UUID","slot":1,"title":"Terminal 1","pid":12345,"launchedOmp":true,"launchProfile":"PROFILE_NAME"}]}
```

`list` is read-only. `sessions` MUST contain every attached session. Clients MAY sort by `slot`.

### 3.2 `inspect`

```json
{"cmd":"inspect","slot":2,"lines":80,"raw":false}
{"ok":true,"id":"SESSION_UUID","text":"RECENT_OUTPUT"}
```

A request MUST select `id` or `slot`; `id` takes precedence. `lines` defaults to `80` and is capped at `1000`. `raw` defaults to false. The server reads at most the newest 65,536 bytes from a bounded PTY-output tail. This is output history, not reconstructed screen state; cursor redraws MAY appear as successive text.

### 3.3 `send`

```json
{"cmd":"send","slot":2,"text":"run the focused test","enter":true}
{"ok":true,"id":"SESSION_UUID"}
```

A request MUST select `id` or `slot` and provide `text`. The server queues UTF-8 bytes to that PTY and appends carriage return when `enter` is omitted or true. `send` is command-capable and MUST be used only with explicit authority over that target terminal.

### 3.4 `message`

```json
{"cmd":"message","from":1,"to":2,"text":"Tests are green."}
{"ok":true}
```

`from` and `to` MUST name live, distinct slots. `text` MUST contain 1–4,000 Unicode characters after trimming. A message is an addressed UI notice; it MUST NOT enter either PTY. V2 has no broadcast.

### 3.5 `open`

```json
{"cmd":"open","profile":"PROFILE_NAME","title":"Worker","confirm":false}
{"ok":true,"confirmed":false,"would":{"slot":3,"profile":"PROFILE_NAME","title":"Worker"}}
```

```json
{"cmd":"open","profile":"PROFILE_NAME","title":"Worker","confirm":true}
{"ok":true,"confirmed":true,"session":{"id":"SESSION_UUID","slot":3,"title":"Worker","pid":12345,"launchedOmp":true,"launchProfile":"PROFILE_NAME"}}
```

`profile` is required; `title` is optional. `confirm` defaults to false. A dry run MUST NOT mutate state. The server chooses the lowest free permitted slot. A confirmed open assigns that slot; UltraTerm MUST attach the returned pane to the workspace.

### 3.6 `close`

```json
{"cmd":"close","slot":3,"confirm":false}
{"ok":true,"confirmed":false,"would":{"slot":3,"id":"SESSION_UUID"}}
```

```json
{"cmd":"close","slot":3,"expectedId":"SESSION_UUID","confirm":true}
{"ok":true,"confirmed":true,"closed":{"slot":3,"id":"SESSION_UUID"}}
```

A confirmed close MUST provide `expectedId` from a fresh dry run. The server MUST reject a missing or changed ID and revalidate `slot → id` under the mutation lock; pre-mutation failure leaves the slot untouched. Success gracefully closes the exact session and UltraTerm removes its slot and pane. If removal commits but a later cleanup step fails, the server returns `ok:false`, `committed:true`, and the `closed` identity while still emitting the closed lifecycle outcome; clients MUST NOT leave a stale pane.

### 3.7 `profile.switch`

```json
{"cmd":"profile.switch","slot":3,"profile":"QUALITY","confirm":false}
{"ok":true,"confirmed":false,"would":{"cmd":"profile.switch","slot":3,"profile":"QUALITY","id":"SESSION_UUID"}}
```

```json
{"cmd":"profile.switch","slot":3,"profile":"QUALITY","expectedId":"SESSION_UUID","confirm":true}
{"ok":true,"confirmed":true,"session":{"id":"NEW_SESSION_UUID","slot":3,"title":"Worker","pid":23456,"launchedOmp":true,"launchProfile":"QUALITY"}}
```

A confirmed switch MUST provide the dry-run ID and revalidate it after profile preflight. It replaces only that session while preserving slot, title, working directory, and dimensions. Startup failure SHOULD restore the previous session and MUST return `ok:false`. UltraTerm attaches the replacement before its startup health check, then repaints every live pane through the same appearance-refresh path used by theme changes. Successful, restored, and unrecoverable outcomes MUST remain distinguishable to the UI.

### 3.8 `register.manager`

```json
{"cmd":"register.manager","from":2,"to":1}
{"ok":true,"from":2,"managerSlot":1}
```

`from` is the worker and `to` its manager. Both MUST exist and differ. The server persists worker-to-manager routes. Multiple workers MAY map to one manager; one worker has at most one current manager.

### 3.9 `task.done`

```json
{"cmd":"task.done","from":2,"text":"Regression suite passed."}
{"ok":true,"deliveredTo":1,"typedIntoPty":true}
```

`from` and non-empty `text` are required; `to` MAY override registration. `text` is limited to 4,000 characters. The server queues the summary plus carriage return into the manager PTY and emits the same addressed notice.

### 3.10 Profile registry

```json
{"cmd":"profiles.list"}
{"ok":true,"profiles":[{"name":"quality","active":false,"builtIn":false}]}
```

```json
{"cmd":"profiles.create","request":{"name":"quality","model":"provider/model","thinkingLevel":"high","titleModel":null,"routing":"upstream/primary,upstream/fallback"}}
{"ok":true,"profile":{"name":"quality","active":false,"builtIn":false}}
```

```json
{"cmd":"profiles.remove","name":"quality"}
{"ok":true,"name":"quality"}
```

Profile operations MUST stay inside the user profile root. Names and model settings MUST be validated. `routing`, when present, is a provider-neutral comma-separated ordered list of upstream model IDs. Creation MUST be atomic. Removal MUST reject active profiles and MUST NOT follow symlinks outside the profile root.

## 4. Universal handoff client

`utp handoff` is a guarded reference-client composition over `open`, `profile.switch`, `register.manager`, `inspect`, and `send`; it is not an additional wire command.

A packet MUST be a current-user-owned, non-symlink regular file under `/tmp`, mode `0600`, containing 1–16,384 bytes. It SHOULD contain: Goal; Current state; Completed; Remaining todos; Decisions and constraints; Resources and artifacts; Next action. It MUST NOT contain credentials, secret values, unnecessary transcript history, or dropped user requirements.

```sh
utp handoff --slot WORKER --profile PROFILE --packet /tmp/handoff.md --manager-slot MANAGER
utp handoff --new-slot --profile PROFILE --packet /tmp/handoff.md --manager-slot MANAGER
```

Confirmation MUST require `--user-authorized`, representing explicit user permission for the exact orchestration. Every handoff requires a live, distinct manager. A confirmed handoff MUST run from that manager terminal or from an external non-UltraTerm shell. In-place confirmation also requires `--expected-id` and registers the manager before replacement. A new-slot handoff registers the new worker and closes that newly opened session if registration or packet submission fails. A manager MAY control multiple workers by repeating the authorized flow. The client waits for the receiver, then submits only a short instruction pointing to the packet.

An agent MAY suggest handoff or scale-out after a dry run reports free capacity and observed system memory is comfortable. It MUST NOT confirm an open, close, switch, or handoff based only on its own suggestion or inferred permission.

## 5. Universal report client

`utp report` is a guarded reference-client extension, not a wire command. It sends one structured JSON payload to a user-owned local hook:

```sh
utp report --route team:group-alias --project project-name \
  --new "A new capability is now available." \
  --changed "An existing experience is easier to use." \
  --fixed "A user-visible problem no longer occurs." \
  --user-authorized
```

`route` is a private local alias for Telegram, a bot, a group, or a generic inbox. The hook owns chat IDs, provider tokens, authentication, final project labels, and delivery. UTP MUST NOT contain or log those values. External delivery requires explicit user authorization or a standing permission and SHOULD happen once, without a duplicate browser or provider call.

The client invokes the executable at `~/.ultraterm/report-hook`, overridden by `UTP_REPORT_HOOK`, and writes the JSON payload to standard input. The hook path and containing directory MUST be current-user-owned. The directory MUST be private; the hook MUST be a regular executable file that is not group/world writable.

For the default `report` kind, the payload contains `route`, `project`, `kind`, and three user-facing item arrays: `new`, `changed`, and `fixed`. At least one item is REQUIRED. Each CLI flag MAY be repeated; each item MUST be a single line of 1–240 characters. A section accepts at most 12 unique items and a report accepts at most 24 items total. Technical workflow details, verification, deployment mechanics, commit identifiers, rollback instructions, and protected values MUST be rejected rather than delivered. The hook renders only non-empty sections under `What's new`, `What's changed`, and `Fixes`, using one bullet per item. Paragraph-style `summary`, `verification`, and `rollback` fields are forbidden for text reports.

For `kind` `file` or `image`, `--file` is REQUIRED and MUST resolve to a regular, non-empty file no larger than 45 MiB whose realpath is sent as `file`; `summary` is an OPTIONAL caption of at most 1024 characters. `new`, `changed`, and `fixed` are forbidden for file and image deliveries.

`utp redact` is a second guarded extension over the same hook. It sends one structured payload:

```json
{"op": "redact", "project": "project-name", "route": "team:group-alias", "message_ids": [3, 7], "reason": "cleanup"}
```

`message_ids` carries 1-20 explicit positive-integer IDs, deduplicated and sorted; `reason` is 1-300 characters. Redaction deletes only the bot's own prior messages, only by explicit message ID — never by content match or bulk range. The hook resolves the chat for the route, deletes each message independently so one failure does not abort the rest, and MUST write a fail-open audit entry for every call. External delivery and redaction require explicit user authorization or a standing permission.

## 6. Security

UTP is a same-user local command boundary. Implementations MUST NOT bind, proxy, or forward it over a network; weaken `0700`/`0600`; follow untrusted profile or packet symlinks; include credentials in protocol traffic, examples, logs, or fixtures; or mutate terminal state without confirmation and identity checks.
