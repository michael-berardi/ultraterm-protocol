# UltraTerm Terminal Protocol v1

This document is the normative UTP v1 wire specification. The key words MUST, MUST NOT, SHOULD, SHOULD NOT, and MAY are interpreted as described in RFC 2119.

## 1. Transport

A UTP v1 server MUST listen on the Unix domain socket `~/.ultraterm/utp.sock`.

- The `~/.ultraterm` directory MUST have mode `0700`.
- The `utp.sock` socket MUST have mode `0600`.
- The server MUST accept same-user local connections only.
- The server MUST NOT expose UTP through TCP or any network listener.
- A stale socket file MAY be removed before the server binds.

A connection carries UTF-8 JSON Lines. Each line MUST contain one JSON object request. The server MUST write exactly one JSON object response line for each request line, in request order. A connection MAY carry more than one request.

A request line MUST NOT exceed 65,536 bytes. An oversized request receives:

```json
{"ok":false,"error":"request too large"}
```

Invalid JSON or a request that cannot be decoded receives:

```json
{"ok":false,"error":"invalid request: DETAILS"}
```

Every successful response contains `"ok":true`. Every command failure contains `"ok":false` and a human-readable string field named `error`:

```json
{"ok":false,"error":"ERROR_MESSAGE"}
```

Unknown top-level request fields MAY be ignored. Command names and response field names are case-sensitive.

## 2. Session object

Commands that return a session use this exact object shape:

```json
{"id":"SESSION_UUID","slot":1,"title":"Terminal 1","pid":12345,"launchedOmp":true,"launchProfile":"PROFILE_NAME"}
```

| Field | Type | Meaning |
|---|---|---|
| `id` | string | Stable session identifier. |
| `slot` | unsigned integer | User-facing terminal number. |
| `title` | string | Current display title. |
| `pid` | unsigned integer | Child process ID, or `0` when unavailable. |
| `launchedOmp` | boolean | Whether UltraTerm launched OMP for this session. |
| `launchProfile` | string or null | OMP profile selected at launch. |

## 3. Commands

### 3.1 `list`

Request:

```json
{"cmd":"list"}
```

Success:

```json
{"ok":true,"sessions":[{"id":"SESSION_UUID","slot":1,"title":"Terminal 1","pid":12345,"launchedOmp":true,"launchProfile":"PROFILE_NAME"}]}
```

`sessions` MUST contain every currently attached session. Ordering is not defined by the wire protocol; clients MAY sort by `slot`.

### 3.2 `inspect`

A request MUST provide `id` or `slot`. If both are present, `id` takes precedence. `lines` is optional, defaults to `80`, and is capped at `1000`. `raw` is optional and defaults to `false`.

Request by slot:

```json
{"cmd":"inspect","slot":2,"lines":80,"raw":false}
```

Request by ID:

```json
{"cmd":"inspect","id":"SESSION_UUID","lines":80,"raw":true}
```

Success:

```json
{"ok":true,"id":"SESSION_UUID","text":"RECENT_OUTPUT"}
```

The server reads at most the newest 65,536 bytes from its bounded PTY output tail, then returns the requested number of final text lines. With `raw:false`, the server removes CSI, OSC, and other escape sequences before applying the line limit. With `raw:true`, the server returns a lossy UTF-8 decoding of the raw bytes.

### 3.3 `send`

A request MUST provide `id` or `slot` and MUST provide string field `text`. If both selectors are present, `id` takes precedence. `enter` is optional and defaults to `true`.

Request:

```json
{"cmd":"send","slot":2,"text":"run the focused test","enter":true}
```

Success:

```json
{"ok":true,"id":"SESSION_UUID"}
```

The server MUST queue the UTF-8 bytes of `text` to the selected PTY. When `enter` is true, the server MUST append carriage return (`0x0d`). It MUST NOT append line feed in place of carriage return.

### 3.4 `message`

A request MUST provide unsigned integer fields `from` and `to` plus string field `text`.

Request:

```json
{"cmd":"message","from":1,"to":2,"text":"Tests are green."}
```

Success:

```json
{"ok":true}
```

`text` MUST NOT exceed 4,000 Unicode characters. The server MUST deliver the message only to the session occupying `to`. UTP v1 has no broadcast message command. A message is a UI notification and is not typed into the target PTY.

### 3.5 `open`

A request MUST provide non-empty string field `profile`. `title` is optional; an empty or whitespace-only title is treated as absent. `confirm` is optional and defaults to `false`.

Dry-run request:

```json
{"cmd":"open","profile":"PROFILE_NAME","title":"Worker","confirm":false}
```

Dry-run success:

```json
{"ok":true,"confirmed":false,"would":{"slot":2,"profile":"PROFILE_NAME","title":"Worker"}}
```

When `title` is absent, `would.title` is `null`:

```json
{"ok":true,"confirmed":false,"would":{"slot":2,"profile":"PROFILE_NAME","title":null}}
```

A dry run MUST NOT create a session. The server chooses the lowest free slot from `1` through `8`.

Confirmed request:

```json
{"cmd":"open","profile":"PROFILE_NAME","title":"Worker","confirm":true}
```

Confirmed success:

```json
{"ok":true,"confirmed":true,"session":{"id":"SESSION_UUID","slot":2,"title":"Worker","pid":12345,"launchedOmp":true,"launchProfile":"PROFILE_NAME"}}
```

The server creates an 80-column by 24-row OMP session with no explicit working directory.

### 3.6 `close`

A request MUST provide unsigned integer field `slot`. `confirm` is optional and defaults to `false`.

Dry-run request and success:

```json
{"cmd":"close","slot":2,"confirm":false}
{"ok":true,"confirmed":false,"would":{"slot":2,"id":"SESSION_UUID"}}
```

A dry run MUST NOT close the session.

Confirmed request and success:

```json
{"cmd":"close","slot":2,"confirm":true}
{"ok":true,"confirmed":true,"closed":{"slot":2,"id":"SESSION_UUID"}}
```

A confirmed close MUST use the implementation's graceful session shutdown path.

### 3.7 `register-manager`

The human-facing CLI command is `register-manager`; its wire command is `register.manager`. A request MUST provide unsigned integer fields `from` and `to`. `from` is the worker slot and `to` is the manager slot. The slots MUST differ and both sessions MUST exist.

Request:

```json
{"cmd":"register.manager","from":2,"to":1}
```

Success:

```json
{"ok":true,"from":2,"managerSlot":1}
```

The server persists the worker-to-manager mapping in `~/.ultraterm/manager-map.json`. A later registration for the same worker replaces its previous manager.

### 3.8 `task-done`

The human-facing CLI command is `task-done`; its wire command is `task.done`. A request MUST provide unsigned integer field `from` and non-empty string field `text`. `text` is trimmed and MUST NOT exceed 4,000 Unicode characters after trimming. Unsigned integer field `to` is optional.

Registered-manager request:

```json
{"cmd":"task.done","from":2,"text":"Regression suite passed."}
```

Explicit-manager request:

```json
{"cmd":"task.done","from":2,"to":3,"text":"Regression suite passed."}
```

Success:

```json
{"ok":true,"deliveredTo":1,"typedIntoPty":true}
```

When `to` is present, it overrides any registered manager. Otherwise, the server resolves `from` through the persisted manager map. The target manager session MUST exist. The server MUST queue the trimmed summary followed by carriage return into the manager PTY and emit the same summary as an addressed terminal message.

## 4. Security requirements

PTY input is command-capable. A UTP server exposed to a network would create a remote command-execution interface. UTP v1 deliberately specifies no network authentication, TLS, remote authorization, or multi-user access because the transport MUST remain a protected same-user Unix socket.

Implementations and packaging MUST NOT:

- bind UTP to a TCP or UDP port;
- proxy or forward the socket to a network service;
- weaken the required directory or socket permissions;
- include credentials in requests, examples, logs, fixtures, or documentation.

A remote operator SHOULD enter the host through an independently authenticated channel, then run the local UTP client on that host.
